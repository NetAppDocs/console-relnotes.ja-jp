=== バックアップとリカバリ



==== Kubernetes ワークロードの機能強化

今回のリリースでは、NetApp Backup and RecoveryでKubernetesワークロード向けに以下の機能強化が導入されています：

* *Trident Protect 26.10*：このリリースには Trident Protect 26.10 が含まれます。
* *ontap-nas-economyおよびontap-san-economyドライバのサポート*：NetApp Trident `ontap-nas-economy`ドライバ（Qtrees）および `ontap-san-economy`ドライバ（LUN）によってプロビジョニングされた永続ボリューム要求（PVC）を保護できるようになりました。economyドライバを使用してPVCを保護すると、基盤となるFlexVolまたはLUN全体が保護されます。これらのバックアップから個々のPVCを復元できます。
* *Kubernetes対応アラート*：アラートは、ボリュームごとではなく、Kubernetesアプリケーションごとに1回送信されるようになりました。
* *ボリュームグループスナップショットのサポート*：Kubernetesアプリケーションを定義する際に、ボリュームグループを作成できるようになりました。ボリュームグループを使用すると、「crash consistent state（障害など予期しないシャットダウン時と同様）」の状態のセットとして複数のボリュームをまとめてスナップショットを取得でき、グループ内のすべてのボリューム間でデータの一貫性を確保できます。
* *S3互換オブジェクトストレージのサポート*：バックアップ対象の認証情報を追加し、保護ポリシーを設定することで、KubernetesアプリケーションのリソースとデータをS3互換オブジェクトストレージにバックアップできるようになりました。


Kubernetesワークロードの保護の詳細については、 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["NetApp Backup and Recoveryを使用したKubernetesワークロードの保護について説明します"^]を参照してください。



==== ONTAP ボリュームワークロードの機能強化

今回のリリースでは、NetApp Backup and RecoveryにONTAP Volumesワークロード向けの以下の機能強化が導入されています：

* *保護レポート*：NetApp Backup and Recoveryでは、ONTAPボリュームワークロードの拡張レポートの作成とダウンロードがサポートされるようになりました。
* *ONTAPシステムの登録解除時にバックアップを保持*：NetApp Backup and RecoveryからONTAPシステムの登録を解除する際に、以前にバックアップしたデータを破棄するか、リストア用に保持するかを選択できるようになりました。NetApp Backup and Recoveryのドキュメントに、システムの登録解除後に保持されたデータをONTAP CLIを使用してリストアする手順が追加されました。


詳細については、 https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-backup-manage.html#unregister-netapp-backup-and-recovery-for-a-system["システムのBackup and Recoveryの登録を解除する"^]を参照してください。

ONTAP ボリュームワークロードの保護の詳細については、 https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-protect-overview.html["NetApp Backup and Recoveryを使用したONTAPボリューム保護について説明します"^]を参照してください。



==== Oracle Databaseワークロードの強化

今回のリリースでは、NetApp Backup and RecoveryでOracle Databaseワークロード向けに以下の機能強化が導入されています：

*別の場所へのリストア*：NetApp Backup and Recoveryは、Oracleデータベースを別の場所（別の登録済みホスト）にリストアできるようになりました。

==== 強化された隔離リカバリ環境構成

Ransomware Resilienceは、強化された隔離型復旧環境の構成ワークフローを提供するようになりました。新しいワークフローにより、クラウドまたはオンプレミス環境用の隔離されたリカバリ環境をセットアップするプロセスが明確化され、簡素化されます。

Ransomware Resilienceは、ユーザーアクティビティ監視を有効にするためのワークフローを改善しました。従来、Ransomware Resilienceは、ワークロード上でユーザーアクティビティ監視を含むランサムウェア対策戦略を有効にするたびに、データコレクターの接続をテストしていました。このアップデートにより、ストレージVMにデータコレクターが存在し、「実行中」の状態であれば、そのチェックはスキップされるようになり、保護ワークフローが高速化されます。

詳細については、link:link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/rp-use-protect.html["ワークロードを保護する"^]を参照してください。



==== Google Cloud NetApp Volumes Flexサービスレベルの一般提供開始

Ransomware ResilienceにおけるGoogle Cloud NetApp VolumesのFlexサービスレベルのサポートが一般提供（GA）となりました。

=== Cloud Volumes ONTAP



==== AzureでのCloud Volumes ONTAP 9.19.1

AzureでCloud Volumes ONTAP 9.19.1の一般提供（GA）バージョンをデプロイおよび管理するために、NetApp Consoleを使用できるようになりました。

コンソールでは、2026年8月からAWSおよびGoogle CloudでのCloud Volumes ONTAP 9.19.1をサポートしています。

https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-new.html["Cloud Volumes ONTAP 9.19.1 リリースノート"^]



==== Cloud Volumes ONTAP のホストでの Azure 暗号化

Cloud Volumes ONTAP 9.19.1 GA以降、前提条件を満たす新しいAzureシングルノードおよび高可用性（HA）デプロイメントにおいて、ホストでのAzure暗号化がデフォルトで有効になります。この機能は、データがホストに書き込まれたりホストから読み取られたりする際に、エフェメラルディスクや関連するホストレベルのキャッシュを含む、VMをホストする物理サーバ上のデータを暗号化します。

AzureにCloud Volumes ONTAPを展開する前に、環境が以下の前提条件を満たしていることを確認してください：

*  `EncryptionAtHost` 機能は、お客様のAzureサブスクリプションに登録されています。 https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli["Microsoft ドキュメント：ホストでの暗号化を有効にする"^]を参照してください。
* 選択したVMインスタンスタイプは、Azureリージョン内のホストでの暗号化をサポートしています。 https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli#finding-supported-vm-sizes["Microsoft ドキュメント：サポートされている VM サイズの検索"^]を参照してください。


以下の点に注意してください：

* 追加の設定は不要です。
* これらの前提条件が満たされていない場合、Cloud Volumes ONTAPの展開でホストでのAzure暗号化は有効になりません。
* ホスト側での暗号化はAzureにのみ適用され、AWSやGoogle Cloudには適用されません。


Microsoftのドキュメント： https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal["Azureポータルを使用して、ホストでの暗号化によるエンドツーエンドの暗号化を有効にします"^]



==== AzureおよびGoogle CloudのCloud Volumes ONTAPクラスタにおけるバックエンドネットワーク暗号化

Cloud Volumes ONTAP 9.19.1以降では、AzureおよびGoogle CloudにおけるHA構成のバックエンドクラスタネットワーク暗号化がサポートされています。

クラスタネットワーク暗号化を有効にすると、クラスタのパフォーマンスに影響を与える可能性があります。この機能を有効にする前に、注意を払い、環境が追加の負荷に対応できることを確認してください。

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-enable-cluster-encryption.html["Cloud Volumes ONTAPクラスタでバックエンドネットワーク暗号化を有効にする"^]



==== Azureの定期メンテナンス中の障害を軽減する機能

定期メンテナンス中、AzureはCloud Volumes ONTAP HAペアのVMを一時的に停止する場合があります。ONTAPはこの一時停止をノード障害と解釈してストレージ処理をパートナーノードに移行し、VMの再開時に元のノードに戻す場合があります（テイクオーバーとギブバック）。このプロセスにより、ノード障害が発生していない場合でも、アクティブなクライアント接続が中断される可能性があります。

Cloud Volumes ONTAP 9.19.1以降では、オプションの設定を有効にすることで、Azureの定期メンテナンスによるフリーズ期間中もHAペアが動作を継続し、自動的にテイクオーバーとギブバックを開始しないようにすることができます。


NOTE: この機能は、Cloud Volumes ONTAP 9.19.1でパブリックプレビューとして利用できます。

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-azure-prevent-freeze.html["Cloud Volumes ONTAP HAペアのAzureメンテナンス中の中断を防止する"^]

[[disaster-recovery]]
=== ディザスタ リカバリ



==== Kubernetesリソースグループのオプションの起動順序

NetApp Disaster Recoveryでは、リソースの優先順位とオプションの遅延時間を指定することで、Kubernetesレプリケーションプラン内のリソースグループのオプションの起動順序を設定できるようになりました。このオプションを使用すると、必要に応じてリソースを同時に起動したり、他のリソースに依存するリソースの起動を遅延させたりすることができ、アプリケーションが正常な状態でオンラインに復帰するのをサポートします。

詳細については、link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/task-replication-plan-kubernetes.html["レプリケーションプランを作成する"^]を参照してください。



==== SnapLockボリュームサポート

Disaster RecoveryでSnapLockボリュームがサポートされるようになり、改ざん防止スナップショットのフェイルオーバーが可能になりました。SnapLockボリュームを使用してフェイルバックを実行する際、フェイルバックを正常に完了させるには、*今すぐスナップショットを取得*オプションを使用する必要があります。

詳細については、link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html["フェイルオーバー"^]およびlink:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failback.html["failback（フェイルバック）"^]の手順を参照してください。



==== 更新とコンプライアンス実行の簡素化

vCenter、レプリケーション計画、およびコンプライアンスの更新の実行は、より迅速な実行を促進するために単一のジョブに簡素化されました。この変更を確認するには、link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/monitor-jobs.html["ジョブの監視"^] の方法をご確認ください。



==== Kubernetesのコンプライアンスチェック

Disaster Recoveryに、Kubernetesワークロードの欠落している作業環境を特定するためのコンプライアンスチェックが追加されました。これらのコンプライアンスチェックは、レプリケーション計画の整合性を保つためにワークロードの健全性を確保するのに役立ちます。

==== ONTAP ボリュームワークロードの機能強化

==== Kubernetes ワークロードの機能強化

今回のリリースでは、Kubernetesワークロードに以下の機能強化が導入されました。

* *Trident Protect 26.08*：このリリースには Trident Protect 26.08 が含まれます。
* *バックアップの再試行*：Kubernetes 保護ポリシーの詳細設定で、バックアップの再試行を有効にし、再試行回数と再試行間隔を設定できるようになりました。
* *部分的なバックアップの成功*：Kubernetes の保護ポリシーの詳細設定で、個々のリソースが失敗した場合でもバックアップを継続するように構成できるようになり、バックアップジョブが部分的に成功した状態として完了できるようになります。これにより、バックアップ操作中に一部のリソースが失敗した場合でも、バックアップされたリソースを復元することができます。
* *「crash consistent state（障害など予期しないシャットダウン時と同様）」の状態およびVM一貫性のバックアップ*：Backup and Recovery for NetApp Consoleサービスで、「crash consistent state（障害など予期しないシャットダウン時と同様）」の状態またはVM一貫性のバックアップやスナップショットを作成する保護ポリシーを設定できるようになりました。また、保護処理中にVMのフリーズを実行する方法をカスタマイズすることもできます。
* *ConsoleエージェントのIPアドレス変更時のKubernetesクラスターの再接続*：Backup and Recovery for NetApp Consoleサービスでは、エージェントのIPアドレスが変更された場合に、クラスターをそのConsoleエージェントに再接続できるようになりました。
* *クラスターを新しいコンソールエージェントに移行する*：NetApp Backup and Recovery コンソールサービスでは、元のエージェントが故障または削除された場合に、クラスターを新しいコンソールエージェントに移行できるようになり、アプリケーションの保護が中断なく継続されます。


Kubernetesワークロードの保護の詳細については、 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["NetApp Backup and Recoveryを使用したKubernetesワークロードの保護について説明します"]を参照してください。
